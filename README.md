# 「KAKKO」

**必要な情報だけ、見せる。**
身分証はあなたの端末内だけで処理されます。

KAKKO は、運転免許証などの本人確認書類を第三者へ提出するときに、不要な個人情報を黒塗りし、**提出先・用途・日付を画像全体に刻んだ「安全なコピー」** をブラウザだけで作る Web アプリです。

> **画像はこの端末内だけで処理されます。KAKKO のサーバーには送信されません。**
> KAKKO はブラウザの Canvas API を利用して画像を加工します。画像アップロード用 API は存在しません。

---

## なぜ作るのか

民泊の予約、アルバイトの応募、賃貸契約、中古品の買取……身分証のコピーを求められる場面は増え続けています。一度送った画像は、送り先で複製され、別の目的に使い回され、漏えいしても取り返せません。

KAKKO は次の 2 つで、そのリスクを小さくします。

1. **見せる必要のない部分を黒塗りする**（本籍、番号、住所の一部など。何を隠すかは利用者が決めます）
2. **「誰に・何のために・いつ」渡したコピーかを画像全体に刻む**（他の用途への転用を心理的・実務的に難しくします）

そして最も大切なこと。**身分証を守るサービス自身が、身分証を収集しない。** KAKKO には画像を受け取るサーバーがありません。

---

## 使い方（30 秒）

1. **画像を選択**（またはサンプルで試す）
2. 画像の上を**ドラッグ / スワイプ**して黒塗り。やり直しは「元に戻す」または ⌘Z / Ctrl+Z
3. **提出目的・提出先・日付**を入力すると、ウォーターマークがプレビューに重なります
   例: `Sakura Guest House / 宿泊本人確認専用 / 2026-09-09`
4. **安全なコピーを作成** → 端末に保存（iPhone では共有シートから写真に保存もできます）

提出目的は「民泊・宿泊」「求人・アルバイト」「賃貸」「中古品買取」「その他」から選べます。
**「求人・アルバイト」を選ぶと、危険な求人の特徴を示す注意喚起が表示され、確認するまでコピーを作成できません。** 加工した身分証であっても、提出先が信頼できなければ提出すべきではないからです。

## 預けた画像の削除を請求する

すでに事業者へ渡してしまった身分証画像については、個人情報保護法に基づく**消去・利用停止・開示の請求文**をブラウザ内で生成できます（フッターの「預けた画像の削除を請求する」、または `#view=delete`）。

- 根拠条文: 第35条第5項（利用する必要がなくなった場合・漏えい等が生じた場合の利用停止等）、第33条第1項・第5項（開示、第三者提供記録）、第36条（拒否時の理由説明）
- 宛先・書類の種類・理由・氏名を入れると請求文が組み上がり、コピー / テキスト保存 / 印刷（郵送用）/ メールアプリで開く、のいずれかで送れます
- 請求文には「本人確認のために画像を再送しない」旨を必ず含めます。削除を求める手紙に免許証を添付するのは本末転倒だからです
- 入力内容は端末の外に出ません。KAKKO の他の機能と同じく、サーバーも保存もありません

これは条文に基づくひな形であり、法的助言ではありません。

## 事業者の方へ: 依頼リンク

身分証の提出を求める側（民泊ホスト、不動産会社、買取業者など）は、**依頼リンク**を渡すだけで KAKKO を自分のフローに組み込めます。登録も API も不要で、リンクはただの文字列です。

```html
<a href="https://<KAKKO の公開URL>/#purpose=lodging&to=Sakura%20Guest%20House&keep=photo,name">
  KAKKO で安全なコピーを作る
</a>
```

| パラメータ | 内容 |
| --- | --- |
| `purpose` | `lodging` / `job` / `rental` / `resale` / `other` |
| `to` | 提出先名（ウォーターマークに刻まれます、60 文字まで） |
| `keep` | 見えている必要がある項目。`photo,name,birthdate,address,number,expiry,domicile,issuer,nationality` から選択 |
| `custom` | `purpose=other` のときの用途名（40 文字まで） |

リンクで開くと、KAKKO は「相手が必要としている項目」と「それ以外は隠して構いません」を表示し、提出先と用途を入力済みにします。**何を隠すかを決めるのは常に提出者本人**で、リンクは相手の希望を伝えるだけです。

パラメータはすべて URL の**フラグメント（`#` 以降）**に載せています。フラグメントはブラウザがサーバーへ送らないため、提出先名がアクセスログに残ることもありません。画像は提出者の端末から事業者へ直接渡り、KAKKO を経由しません。

アプリのフッター「事業者の方へ: 依頼リンクを作る」（`#view=business`）から、リンクを対話的に生成できます。

## プライバシー設計

| 設計 | 実装 |
| --- | --- |
| 画像処理は 100% ブラウザ内 | `src/lib/render.ts` / `export.ts` が Canvas API だけで完結 |
| 画像を受け取るサーバーが存在しない | `wrangler.jsonc` に Worker スクリプト (`main`) なし。静的アセット配信のみ |
| ブラウザ自身に外部通信を禁止させる | CSP `connect-src 'none'`（`public/_headers` と build 時に注入する `<meta>` の二重掛け） |
| 画像を永続化しない | LocalStorage / IndexedDB / Cookie 不使用。状態は React のメモリ上のみ |
| EXIF / GPS を出力に残さない | 新しい Canvas に描画し直して `toBlob` で再エンコード |
| 外部リソースなし | 外部フォント・CDN・アナリティクス・トラッカーは一切なし |
| 実行時依存は最小限 | `react` と `react-dom` のみ |

これらは**規約ではなく機械的に検証**しています。

- `src/lib/security.test.ts` — ソース全体に `fetch` / `XMLHttpRequest` / `sendBeacon` / `localStorage` などが存在しないこと、`_headers` の CSP が `scripts/csp.ts` と一致すること、`wrangler.jsonc` にサーバーコードやストレージのバインディングがないことを検査
- ランタイムテスト — `fetch` などを「呼ばれたら例外」に差し替えたうえで、読み込み → マスク → ウォーターマーク → 書き出しの全パイプラインを実行
- ESLint `no-restricted-globals` — ネットワーク API や永続化 API を書いた時点で lint エラー
- CI — ビルド成果物に想定外の外部 URL が含まれていないことを grep で検査

### Content Security Policy

本番:

```
default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self' blob:;
font-src 'self'; connect-src 'none'; media-src 'none'; object-src 'none';
worker-src 'none'; child-src 'none'; frame-src 'none'; manifest-src 'self';
form-action 'none'; base-uri 'none'; upgrade-insecure-requests
```

`img-src blob:` は、選択したファイルを一時的な Object URL としてデコードするためだけに必要です（メモリ上の URL で、ネットワークには出ません）。

開発時 (`npm run dev`) は Vite の HMR（WebSocket）と React プラグインのインラインスクリプトが必要なため、`vite.config.ts` 内のプラグインが**開発サーバーのレスポンスヘッダーだけ**緩い CSP に差し替えます。緩い CSP はビルド成果物に含まれません。

- npm

### 将来のルールエンジン

`src/rules/purposeRules.ts` は UI から独立したデータ構造です。各目的は `maskHints: MaskHint[]` を持っており、MVP では空です。将来「この用途なら、この項目はマスク推奨」という提案を追加する場合は、この配列に `{ field, reason }` を足すだけで UI 側へ渡せます。**座標を推定したり、法的に「隠してよい」と断定する機能は意図的に持たせていません。**

### テスト

最低限、次を検証しています。

- マスク矩形を追加できる（ポインタ操作・キーボード数値入力）
- Undo / Redo / 個別削除ができる
- ウォーターマーク文字列が生成される（空欄の省略、「その他」の自由入力）
- 画像を書き出せる（新規 Canvas、PNG / JPEG、サイズ上限、EXIF を持たない再生成）
- 入力画像がネットワーク送信されない設計になっている（静的検査 + ランタイム検査 + CSP + wrangler 設定）
- 「求人・アルバイト」で警告が出て、確認するまで書き出せない

### サンプル画像

`public/sample/sample-id.png`（と元の `.svg`）は**完全に架空**のデータで作ったデモ用画像です。実在の書類デザインを再現したものではなく、大きく「SAMPLE」「FICTIONAL ID · DEMO ONLY」と入っています。**実在する身分証画像は絶対にリポジトリへ含めないでください**（`.gitignore` で `*.jpg` / `*.heic` などを既定で除外しています）。

## Cloudflare へのデプロイ

```bash
npx wrangler login        # ブラウザで Cloudflare にログイン（トークンはリポジトリに保存されません）
npm run deploy            # build → wrangler deploy
```

初回はアカウントの workers.dev サブドメインの登録を求められます。`kakko` を選ぶと、Worker 名が `app` なので公開 URL は `https://app.kakko.workers.dev` になります。

`wrangler.jsonc` は静的アセットのみを指定しています。**`main`（Worker スクリプト）や R2 / D1 / KV / AI などのバインディングを追加しないでください。** それはこのプロジェクトの最重要原則を壊します（テストが失敗します）。

環境変数・シークレットは不要です。そのため `.env.example` も置いていません。将来必要になった場合も、秘密値は `.dev.vars` や Cloudflare のダッシュボードにだけ置き、Git には含めないでください。

## セキュリティ上の考え方

- **収集しないことが最大の防御。** 攻撃対象となるサーバー側のデータが存在しません。
- **ポリシーで縛るのではなく、コードとテストで縛る。** CSP・lint・テスト・CI の 4 層で「送信しない」を保証します。
- **依存を増やさない。** 実行時依存は React のみ。サプライチェーンリスクを最小化します。
- **`eval` / `new Function` / `dangerouslySetInnerHTML` 禁止。** ESLint で強制します。
- **ユーザー入力はサニタイズ。** 提出先・用途の文字列は制御文字を除去し長さを制限してから Canvas とファイル名に使います。
- **メモリ上で完結し、閉じれば消える。** Object URL は使用後すぐに revoke、書き出し用 Canvas は生成後にサイズ 0 で解放します。
- **iPhone Safari を考慮。** 書き出しサイズを長辺 3000px に制限し、Canvas のメモリ上限を超えないようにしています。

脆弱性を見つけた場合は [SECURITY.md](./SECURITY.md) を参照してください。

### 正直に書いておくこと

- 黒塗りは**不可逆**です（ピクセルを完全に上書きします）が、**画像の外側**、たとえば提出先がスクリーンショットを撮る、印刷する、といった行為は防げません。
- ウォーターマークは転用の**抑止**であって、技術的に転用を**不可能**にするものではありません。
- KAKKO は「加工すれば何にでも安全に提出できる」ツールではありません。提出先が信頼できない場合の正解は「提出しない」です。

## 法的助言ではありません

KAKKO は法的助言を提供するサービスではありません。どの項目を隠してよいか、身分証の提出が求められる場面で何が適法・適切かは、提出先の案内や公的機関の情報を確認し、ご自身で判断してください。MVP では法的判断を自動化する機能を意図的に実装していません。
